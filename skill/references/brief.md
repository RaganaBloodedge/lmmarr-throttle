# brief：把冷存储重拼成一段指引

**一句话**：新会话不该重读历史，只该读一段从冷存储重拼出来的 brief。

这正是最初的诉求：

> 「很多历史对话不应该直接重复投喂给 LLM，而是根据任务描述和索引找到本地冷存储的历史对话，
>   重新拼成一段**指引性的**，回喂给 LLM」

## 输出形状

```
【任务】api-retry · 支付接口重试策略  [doing 40%]
已定指数退避，待补熔断
【已定】
- #1 改用指数退避，基准 200ms
- #2 接入熔断器，阈值 50%
【坑】
- #3 熔断器默认半开窗口太短 → 误放流量；处理=调到 30s
【未决】
- #5 并发压测下 P99 抖动未定位（复现：50 并发连跑 10 分钟）
【下一步】补熔断器单测
【指针】MEMORY_api-retry.md / JOURNAL_api-retry.md（细节按需取，不要整份读回）
```

段与「任务」信息来自两处：
- `【任务】` 与摘要行 ← `MEMORY_<id>.md` 的 frontmatter
- `【已定】/【坑】/【未决】/【下一步】` ← `JOURNAL_<id>.md`

任务文件不存在时（只有 journal），brief 照样能出，只是没有任务标题与摘要。

## 三条性质

| 性质 | 说明 |
|---|---|
| **零 LLM 调用** | 纯模板 + 关键词计数打分。便宜到可以每轮跑，且不引入新的失真 |
| **有预算** | 默认 ≤1200 字符（`--max` 可调） |
| **只给指针** | brief 本身不搬运原文，细节回冷存储取 |

## 选择与排序

- 给了关键词 → 按**命中次数**降序；同分则**新的在前**。
- 没给关键词 → 全 0 分，退化为"越新越靠前"。
- 每个类型默认取 `did:3 / pit:2 / open:2`，最后按序号升序还原**时间顺序**呈现。

## 预算与截断

**超预算时先丢条目，丢条目也算截断，必须说出来。**

丢弃顺序（最不重要的先丢）：`did` → `pit` → `open`。
`next` 与 `指针` 是 pinned，永不被丢 —— 这两样是"下一步去哪"和"细节去哪找"，丢了 brief 就没用了。

截断发生时输出末尾会带一行 `（已按预算截断，细节见上方指针）`。
静默丢东西是这套东西最不该犯的错：模型会以为自己看到的是全貌。

## 什么时候跑 brief

- **新会话/新任务开工前** —— 用它替代"重读历史"。
- **上下文逼近上限时** —— 手动收束一下当前任务的状态。
- **交接给另一个会话/另一个人时**。

不要每轮都跑。它的定位是"进场的第一个动作"，不是"每轮的背景音"。
