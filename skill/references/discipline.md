# 纪律：三条杠杆、三条红线、委派契约

这一部分是**建议层**（skill 没有强制力，模型可以选择不听）。
需要强制力的部分见 `docs/DESIGN.md` 的「岔路」——那要上插件层的 hook。

## 三条杠杆（按收益排序）

| 杠杆 | 手段 | 为什么排这个次序 |
|---|---|---|
| **① 转数** | 组合型操作固化成执行器（一行调用 = 一轮） | 收益是第二名的两倍：多一次调用的边际成本，绝大部分是"再发一遍上下文"，不是工具内容本身 |
| **② 每轮上下文体积** | 读前先 grep 定位、`Read` 必带 limit、输出去字节留结论 | 直接乘在每一次调用上 |
| **③ 重复读** | 同文件不重复读；大块探索走子代理 | 实测过半的文件被读过不止一次 |

## 三条红线（反直觉，勿踩）

1. **绝不"把历史压缩重写"。** 缓存命中率高的时候，任何改写**已缓存前缀**的动作
   会把便宜的命中变成贵的全价，**成本反而上升**。
   正解：只对"今后新产生的内容"节流，不动已缓存的前缀。
2. **绝不静默截断。** 丢东西必须说出来（brief 已内建；自己写执行器时也要守这条）。
3. **绝不把读回来的东西写回记忆。** 回答一个查询是只读操作；
   把刚检索到的内容当"新知识"再存一遍，是记忆库自我膨胀的主要来源。

## 委派契约（delegate 路线）

子代理**看不到主流程的历史**，所以 brief 必须自包含：

```
【目标】<一句话：这次要回答什么问题>
【已知】<关键事实，≤5 条>
【产出】<只要结论，格式：...>
【禁区】不要回贴原文；不要回贴中间过程；不要复述文件内容
```

**返回契约**：默认子代理只回最终消息，但要在 prompt 里钉死"只回结论 + 指针"，
否则它会把读到的原文再吐一遍 —— 那就白隔离了。

## 触发条件（长程任务才启用）

- **短程任务不启用**：一次性、几步就完的，固化/委派的成本摊不平，包住只会更慢。
- **足够长才触发**，信号是其中之一：
  - 同一模式**第二次**出现（→ 该固化成执行器）
  - 上下文开始**逼近上限**
  - 任务**已跨多轮**且还在继续

好消息：skill 的加载模型本身就是"启动只挂 name + description，正文按需加载"——
**不启用时零成本**。

## 边界（必须说清，否则会期望错）

| 能做 | 做不到 |
|---|---|
| 压**入口**：执行器、grep+limit、不重复读 | ✗ 让**已经在窗口里**的旧观测消失 |
| 把结论沉淀成 journal + 指针，此后不再引用原文 | ✗ 改写已缓存的前缀 |
| 用 brief 让新会话**不去重读**历史 | ✗ 在会话中途"回填"压缩 |

准确的说法：**skill 管"入口"，框架管"窗口里"。**
掩码（就地退休逐步依赖型探索）是插件层能力——模型改不了自己已经进窗口的旧观测。
